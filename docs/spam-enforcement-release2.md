## Architecture and configuration

Salesforce Web-to-Lead is the sole token verifier. Google checkbox v2 tokens are single-use;
website preverification would consume the token before Salesforce receives it. The shared widget
loads Google's classic `api.js`, keeps one token per mounted form in memory, and resets after an
action or expiry. Its 90-second local lifetime reserves 30 seconds for server admission. Server
validation is still authoritative; client clocks and token shape do not establish validity.

| Server-only variable | Meaning |
|---|---|
| `VPCS_RECAPTCHA_PROFILE` | Must equal the validated Salesforce profile (`webdev` or `production`) |
| `VPCS_RECAPTCHA_SITE_KEY` | Public checkbox site key from the correct environment's Google key |
| `VPCS_SALESFORCE_RECAPTCHA_KEY_NAME` | Exact key-pair name generated by that Salesforce org |

The public provider receives only the mode and site key. Missing or mismatched settings make
verification unavailable and block fresh dispatch. Mock uses no provider and no credentials.
Keep the legacy secret in Salesforce's native key-pair registration; never add it to the website,
public variables, source, test traces or logs. No Google service account or custom verification
API is required by this native integration.

The shared service inspects/reconciles an existing attempt before requiring a fresh challenge.
For new attempts, missing/malformed tokens cannot create a claim, enrich a partner or dispatch.
Final serialization replaces client settings with the approved key name, current org ID,
`fallback: "false"`, current millisecond timestamp and `g-recaptcha-response`. These fields stay
outside the payload HMAC. Existing confirmed work remains reconcilable when CAPTCHA expires or
configuration becomes unavailable. A native POST without a matching persisted Lead remains
**unconfirmed**; a new widget/token never authorizes another POST for that reference.

Google documents token lifetime and single use in its [verification guide](https://developers.google.com/recaptcha/docs/verify).
Salesforce documents its [native Web-to-Lead setup](https://help.salesforce.com/s/articleView?id=sf.setting_up_web-to-lead.htm&language=en_US&type=5).
